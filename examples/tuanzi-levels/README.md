# 《团子蹦蹦》20 关：开发配置与验收 v1.0

日期：2026-10-29。状态：**可接入的玩法原型数据，不是已实现或已真机验证的游戏**。按现有顾问的 `references/level-mechanics.md` 复用“新题/同质/冲突”矩阵、四段节奏、每 5 关呼吸关及目标/时限/密度/容错/奖励字段；参考 `assets/templates/dev-spec.md` 的可验收结构，未改写 Skill。当前仓库仅见顾问文档，未发现游戏工程。阶段、参数、失败率和奖数都是本次设计假设，需试玩调优。

## 玩法和机制矩阵

操作只有点击屏幕跳跃；角色自动向右前进。前两关的地面金币自动碰到，第三关开始增加空中可选金币；通关需抵达终点并收够金币。5 种可组合设计：普通障碍、连续跳（两障碍间落地再跳）、金币、上下移动障碍、速度区域。跳跃为基础动作，不额外增加按键。移动障碍上下浮动，不横移；速度区域内速度恒定，入口/出口瞬间变化，并提前展示箭头提示。

| 组合 | 评价 | 带来的决策或处理 |
|---|---|---|
| 普通障碍 × 连续跳 | 新题 | 单次起跳后须预留落点并再次点击 |
| 普通障碍 × 金币 | 新题 | 跳越时能否兼顾空中金币；地面金币作为保底 |
| 普通障碍 × 移动障碍 | 新题 | 根据障碍高度和相位调整起跳时机 |
| 普通障碍 × 速度区域 | 新题 | 重新估计距离和起跳时机；进入前提示 |
| 连续跳 × 金币 | 新题 | 规划连跳中取币，不强制取空中币 |
| 连续跳 × 移动障碍 | 新题 | 同时留意落地与下一障碍相位 |
| 连续跳 × 速度区域 | 同质 | 决策仍是连续落地起跳，后期仅少量作为节奏变奏 |
| 金币 × 移动障碍 | 新题 | 决定是否冒险取空中币，地面币仍能满足目标 |
| 金币 × 速度区域 | 同质 | 速度影响时间窗口，不单独当作新机制 |
| 移动障碍 × 速度区域 | 冲突风险 | 位移与速度变化叠加易读性下降；先独立教学、显示区域，配置只用低幅移动和 1.08～1.10 倍速度，需真机复核 |

## 数据契约与接入

1. `levels.json` 为唯一关卡数据源，UTF-8，`schemaVersion=1.0.0`；每个 `levels[]` 是完整关卡。`obstacles`、`coins`、`speedZones` 中所有 x 均是世界坐标，起点 x=0，终点 x=`length`；x 向右，y 向上，地面 y=0；障碍 x 是中心，移动障碍 y 是底部，角色 x 为中心、y 为底部；金币 x/y 为圆心。
2. 角色碰撞盒宽 0.36、高 0.40；障碍宽 0.45、高 0.32。`moving` 的底部位置为 `liftAmplitude * (1 - cos(2π * t / periodSeconds + phaseRadians)) / 2`，t 从本局开始累计且暂停时冻结。静止障碍底部为 0。角色与障碍 AABB **严格重叠**才算碰撞，边界恰好接触不算；每个障碍每次尝试最多记 1 次，前进不减速、不反弹；同时多个不同障碍分别计数。金币是圆与角色 AABB 相交（含相切），同一枚每局只能拾取一次。
3. 起跳为固定初速度，按下持续时间不改变高度；仅落地、土狼时间或落地缓冲有效时允许一次起跳，空中无二段跳。`coyoteSeconds=0.08`：离开可站地面后的一段宽限；`bufferSeconds=0.10`：落地前点击可缓存一次，落地后立即消费，重复点击不会累积多次。持续按住不自动连跳。地面连续，宽限主要为未来地形兼容；当前 20 关无缺口。
4. 无空气阻力、无变高跳：离地高度 `h(t)=5.2t−7t²`，理论峰值约 0.966 WU，往返地面约 0.743s。运行采用固定步长 1/120s 或等效连续碰撞检测；渲染帧率独立，不跳过碰撞。速度由 `baseSpeed × 当前区间 speedMultiplier` 决定，区间采用 `[startX,endX)`；不重叠。`speedTransition` 为瞬变，无加减速曲线。镜头和屏幕坐标只影响展示，不改变世界数据。
5. 状态 `ready → running → success / failure → retry`。计时仅在 running 的有效模拟时间流逝；进入后台或暂停冻结位移、相位、计时和输入缓存。每步先处理障碍和金币，再判断 `mistakes > maxMistakes` 或 `time > timeLimitSeconds`，再判断是否抵达终点：金币足够则成功，不足即失败。时间恰好等于上限不超时；同一时刻伤害超限优先于终点。奖励仅对一次成功尝试结算一次，用该次 attempt ID 幂等；失败不结算。重试彻底重置金币、碰撞记录、时钟、坐标、速度、输入缓存、运动相位及结算状态。若用户继续重玩已过关关卡是否重复发奖励，产品层应另定，本配置不推断。
6. 加载时校验 schema 和未知类型，拒绝未知版本、重名 ID、越界数据；**不要静默忽略未知机制**。把 JSON 映射到引擎的世界坐标和组件，进行 1/120s 或等效扫掠碰撞的固定物理步；先用占位图形验证再替换素材。视觉障碍与碰撞框应一致，至少提供调试显示框。每关地图在终点后留屏幕缓冲，避免视觉截断。
7. 在本目录运行 `python3 validate.py`。脚本检查 1–20 编号、部分数值范围、对象 ID、依赖、目标与密度，并以 120Hz 理想模型对每关跑一条自动起跳路径。**这不是完整 JSON Schema 校验、无障碍证明、平衡性或引擎/真机测试**；浮动障碍其他相位、输入延迟、掉帧和实际玩家通关率需专项测试。单位换算、屏幕适配、帧同步与输入由实际引擎实现。

## 前三关详细验收

前提：加载原始 JSON、开启显示碰撞盒和调试时间/位置/计数；分别在 30、60、120 FPS 渲染下使用固定物理步。开发机先自动化复现，再用抖音开发者工具与至少一台目标手机复测。以下是**执行方案，不是已经测得的结果**。

| 关卡 | 操作与测试输入 | 可观察的通过标准 |
|---|---|---|
| 1 樱花草地 | 不点击到首障碍 x=8；再重试，接近障碍前点击；分别在早/中/晚位置取样；持续按住及空中重复点按 | 角色自动以 2.6 WU/s 前进；一次按下只起跳一次；空中重复按不产生二段跳；理论峰值约 0.966、飞行约 0.743s，固定步模型误差各 ≤0.03 WU / 0.03s；不跳撞障碍记 1 次，前两次不失败、第三次立即失败；收集至少 2 枚后到终点成功 |
| 2 樱花草地 | 依次通过 4 个障碍；在每次落地前 0.05s 点一次，再试落地前 0.12s；同一障碍保持重叠多帧 | 0.05s 输入缓存落地后触发一次，0.12s 的输入已过期不触发（以物理时间测量）；每个障碍最多记一次碰撞；连续障碍间可落地再跳；至少 3 金币抵终点成功 |
| 3 樱花草地 | 经过地面和障碍上方金币；同一金币重叠多帧；分别以 2 与 3 个金币抵终点 | 单枚最多计数一次；3 枚及以上抵终点成功，2 枚抵终点立即显示目标未完成并失败；空中金币是可选项，地面 5 枚足以完成目标 |

**碰撞边界与一致性：** 用调试工具将角色碰撞框与静态障碍分别放在完全分离、边缘相切、重叠 0.01 WU 的位置；前两者不记撞击，最后一次记 1 次；从左向右高速通过障碍仍不能穿透漏判。金币相切则计入。测每种渲染帧率 10 次相同脚本，结果和障碍/金币 ID 集合一致，物理步位置误差 ≤0.03 WU。运动状态、命中数、已收金币与失败原因均需在调试记录中可见。

**失败与重试：** 三关分别覆盖撞击超容错、超时和终点收集不足；检验一帧同时满足失败和终点时失败优先。进入失败界面点击重试，角色、速度、y/垂直速度、计时、金币、障碍命中记录、移动相位、输入缓存均恢复初始；重复点击重试不生成多个角色/计时器。成功状态重复触发结算回调只结算一次；暂停/切后台 10 秒再恢复，模拟时间与对象相位不跳变。以上逐项记录设备、系统、引擎版本、FPS、结果和缺陷编号。

**手感观察：** 各关邀请至少 5 位未经训练的玩家试玩并记录样本数、每次尝试成功/失败原因、用时、点击位置、首跳延迟和主观反馈；这个样本仅用于发现问题，不足以证明失败率达标。累计有足够数据后按关计算失败尝试数/总尝试数，与目标带比较；若第 8–12 关失败集中或连续失败过多，优先加提示、拉开间距或增加容错，再重新测试。

## 抖音平台边界

本包是通用玩法数据，不包含微信或抖音平台 API、工程入口、广告、登录、支付、存档及审核结论。接入时由实际项目的引擎适配抖音小游戏的触摸、生命周期、屏幕安全区、性能和资源加载；逐项核对抖音开放平台**当时最新官方文档与后台要求**，并在开发者工具及真机验证。微信 Skill 中的微信入口、能力、主体与审核表述不得直接当成抖音规则。数据文件本身不能直接发布或运行。
