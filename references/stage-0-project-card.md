# 阶段 0 · 立项决策卡

用于回答"这款小游戏能不能做、要花多久、卡在哪"。四问定生死：玩法一句话能否说清、主体是否企业、变现是广告还是内购、团队能否撑到版号下批。

## 一、形态边界：小游戏 / 小程序 / App 游戏

| 维度 | 微信小游戏 | 微信小程序 | App 游戏 |
|---|---|---|---|
| 渲染方式 | Canvas / WebGL（无 WXML/WXSS） | WXML + WXSS + 逻辑层 | 原生 / 引擎原生 |
| 入口文件 | `game.js` + `game.json` | `app.js` + `app.json` | 无平台约定 |
| UI 构建 | 需自绘或引擎 UI 系统 | 平台组件 + 样式 | 自建 |
| 代码包限制 | 主包 + 分包有上限（历史口径主包约 4MB、整包约 20MB，**需核对官方文档**） | 主包 + 分包上限（历史口径主包 2MB、整包 20MB，需核对） | 无 |
| 开放能力 | 开放数据域（好友排行等，隔离渲染） | 无开放数据域 | 平台 SDK |
| 主体资格 | **仅企业/组织**，个人不可注册 | 个人可注册部分类目 | 开发者账号 |
| 版号 | **上线前置** | 一般不需要 | 依渠道要求 |
| 虚拟支付 | 需版号 + 平台能力开通 | 不适用 | 依渠道 |

结论写法：先判形态，再判"用户手上有没有企业主体"。没有企业主体 → ❌ 直接进入不可行结论，或改走 H5/独立 App 路线（成本结构完全不同）。

## 二、主体与资质前置

| 项 | 谁办 | 周期量级 | 备注 |
|---|---|---|---|
| 企业主体 + 微信认证 | 用户 | 天级 | 小游戏注册的前提 |
| 软件著作权（软著） | 用户 | 通常数十个工作日，可加急 | 版号材料的常见组成，名称须与游戏名一致 |
| 游戏版号 | 持证出版单位申报 | 以月计，波动大 | **不可自行申报**，须经有资质出版单位 |
| 类目/资质补充 | 用户 | 视类目 | 涉及社交、支付、内容展示等可能加资质 |

红线：软著与版号只给路径与材料清单，不代编造、不代申请、不教绕过。

## 三、成本与时间预估（三档模型）

| 档位 | 玩法复杂度 | 美术 | 团队 | 到可上线的时间量级 |
|---|---|---|---|---|
| 轻量休闲 | 单一核心机制 + 循环关卡 | 2D 扁平/买量素材风 | 1 程序 + 1 美术（可兼职策划） | 数周开发 + 资质周期 |
| 中度 | 3–5 条机制组合 + 成长线 | 2D 精绘 + 动效 | 2 程序 + 1–2 美术 + 策划 | 2–4 个月 + 资质周期 |
| 重度（含剧情/角色） | 多系统 + 剧情分支 + VO | 立绘 + 场景 + UI 全套 | 5 人以上 | 4 个月以上 + 资质周期 |

总排期公式：`开发周期 + 提审整改周期 + 资质周期`，三者并行度决定真实上线日。资质是长尾项，**从 Day 1 就要启动**。

## 四、版号风险四级结论

- ✅ 通过：已有版号，或已签约持证出版单位且材料齐备。
- ⚠️ 注意：版号在申报中，需明确"上线前必须拿到"，并把灰度/预约页作为过渡。
- ❌ 禁止：无版号却计划开内购、或在提审时以"测试"名义绕过版号上线。
- ❌ 禁止：伪造软著/版号材料、借用他人版号。
