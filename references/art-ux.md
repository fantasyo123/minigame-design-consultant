# 阶段 3 · 美术方向与 UX

美术不是"好看就行"，是"能不能被 3 秒看懂、能不能在小屏上读清、能不能低成本量产"。UX 的第一战场是首次 60 秒。

## 一、美术风格定位三件套

只给形容词（"清新""国潮"）无法执行。必须落到：

1. **参考图 3–5 张**：风格锚点 + 反面参考（明确不要什么）。
2. **色板**：主色 1、辅色 2、强调色 1、背景 2，全部给十六进制值。
3. **字体与字号阶梯**：标题/正文/数字/提示四级，写明字重与最小字号（小屏正文不小于 24px 视觉尺寸）。

| 风格 | 特征 | 适合品类 | 量产成本 | 风险 |
|---|---|---|---|---|
| 扁平矢量 | 纯色块、无描边、几何 | 超休闲、拼图 | 低 | 同质化，靠动效撑差异 |
| 卡通描边 | 粗描边 + 高饱和 | 消除、闯关 | 中 | 描边过粗在小屏糊 |
| 像素 | 低分辨率网格 | 复古、roguelike | 低–中 | 动效与UI需同风格统一 |
| 精绘 2D | 厚涂/水彩，细节多 | 剧情、养成 | 高 | 包体与工期双高 |
| 3D 低模 | 低面数 + 平面着色 | 休闲 3D | 中–高 | 引擎与性能门槛 |

选型原则：**团队产能决定风格，不是喜好决定风格**。只有 1 名美术时，精绘 2D 会拖死项目。

## 二、微信小游戏的设计语言要点

- 竖屏优先，安全区留白（刘海/底部手势区）。
- 单屏信息密度低，一屏一个主行动按钮。
- 首屏即玩法，不做长 Logo 动画（用户 3 秒决定去留）。
- 触控热区不小于 44×44 视觉像素，边缘留 ≥ 16px 防误触。
- 弱网与低端机是常态：动效降级方案要提前定（关粒子、降帧）。

## 三、反馈层级（打击感的三层）

| 层 | 手段 | 时长 | 缺了会怎样 |
|---|---|---|---|
| 视觉 | 缩放/位移/闪白/粒子 | 80–200ms | 手感"飘" |
| 听觉 | 命中音、连击音高递增 | 同步 | 反馈"钝" |
| 触觉 | 短振动（平台支持时） | ≤ 30ms | 高潮"平" |

数值反馈口诀：**数字要跳、颜色要变、声音要跟**。三者缺一，玩家会觉得"没打中"。

## 四、首次 60 秒体验脚本

| 时间 | 玩家看到 | 系统做什么 |
|---|---|---|
| 0–5s | 一屏内可玩的局面 | 不弹窗、不要授权、不要登录 |
| 5–15s | 第一次成功操作 + 强反馈 | 隐式教学（高亮可点区域） |
| 15–30s | 第一个小目标达成 | 首次奖励，建立"操作→收益"认知 |
| 30–45s | 难度微升，第一次失败或险胜 | 失败也要给"差一点"的信息 |
| 45–60s | 结算 + 下一局入口 | 此刻才提授权/登录/加桌 |

授权时机红线：首次启动**不要**先弹登录/授权，先给玩法。授权弹窗放在玩家已获得价值之后，转化率与通过率都更高。

## 五、界面规范清单

- 主界面：主行动按钮唯一且最大；次要入口弱化到图标。
- 结算页：结果 > 奖励 > 下一步，三层信息从上到下。
- 设置页：音效/音乐/振动三个开关必备，隐私与用户协议入口必备。
- 弹窗：同时最多 1 个；关闭按钮常显且热区足够。
- 加载：超过 1 秒必须有进度反馈，不出现纯白屏。

## 六、音频与 VO 规划

| 类型 | 数量建议（轻量） | 备注 |
|---|---|---|
| BGM | 2–3 首（主界面/关卡/结算） | 循环点要无痕，避免爆音 |
| 音效 | 15–30 个 | 命中、连击、失败、按钮、奖励 |
| VO | 按剧情体量定，见 narrative.md | 需标注时长与文件大小预算 |

包体敏感：音频常是包体大头，优先用短音效 + 分段 BGM，必要时走分包或远程加载（遵循平台资源加载规范）。

## 七、体验规范交付格式

```markdown
## 体验规范：<游戏名>
1. 风格定位：<三件套>
2. 色板：主 #RRGGBB / 辅 / 强调 / 背景
3. 字号阶梯：标题 / 正文 / 数字 / 提示
4. 反馈层级：视觉 <描述> / 听觉 <描述> / 触觉 <描述>
5. 首 60 秒脚本：<表格>
6. 界面清单：<页面 × 元素 × 状态>
7. 音频预算：BGM x 首 / 音效 x 个 / VO x 句 ≈ x MB
8. 降级方案：低端机与弱网如何处理
```
