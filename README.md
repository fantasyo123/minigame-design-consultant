# 微信小游戏策划与玩法设计顾问

把小游戏创意整理成立项决策卡、核心循环、关卡方案、美术体验规范和开发规格说明书。交付物是策划文档，不包含可运行的游戏工程。

> Skill 是给 AI 助手使用的工作方法和参考资料；实际执行能力取决于宿主工具、权限和环境。中文名称用于说明展示，英文仓库地址保留以方便安装与更新。

## 新手从这里开始

### 1. 准备什么

准备玩法方向、目标人群、单局时长、团队规模、预算、排期及计划的变现方式。不清楚的项直接写“待定”；纯策划体验不需要先安装游戏引擎。

### 2. 下载并加载技能

1. 在本页面点击绿色 **Code → Download ZIP**，解压到你能找到的位置。
2. 本项目入口是 [SKILL.md](SKILL.md)。保留整个技能文件夹，不能只复制 README 或单个 SKILL.md；入口引用的相对路径文件也需要一起保留。
3. 在支持本地文件的 AI 助手中打开解压目录，明确要求“读取 `SKILL.md` 并按该技能处理接下来的任务”。如果助手无法读取电脑文件，使用该产品支持的文件导入方式；只粘贴 README 不等于加载完整技能。
4. 想要长期自动调用时，按下方安装章节放入宿主的技能目录，然后重新打开会话；不同产品的目录和工具权限可能不同。
5. 先询问：“请说明刚加载的技能名称、能做什么、当前缺少哪些工具。”确认识别正确后再执行任务。

命令行下载（可选，需要已安装 Git；在你存放项目的目录执行）：

```bash
git clone https://github.com/fantasyo123/minigame-design-consultant.git
```

### 3. 复制这段话开始第一次使用

```text
请读取 SKILL.md，我想策划一款整理行李的休闲小游戏，目标是每天玩 5—10 分钟的上班族，团队 2 人，预算和主体资质待定。先做立项决策卡和最小玩法闭环，列出需要核实的问题，不写代码，不把尚未核实的平台政策当成结论。
```

### 4. 你应该得到什么

立项决策卡、核心循环、第一版范围、待确认事项及下一步责任人。之后可继续让助手细化 10 个示例关卡，并按 assets/templates/dev-spec.md 整理开发规格。

### 新手推荐路线

1. **确定范围**：一句话讲清玩家做什么、为什么有趣；先做一个可验证的核心循环。
2. **设计关卡**：从教学、变奏、叠加到考核，注明目标时长与失败条件。
3. **设计体验**：明确首次一分钟流程、界面反馈、美术参考和声音需求。
4. **核对上线条件**：按实际主体、地区、产品类型和变现方式查证最新官方要求，记录出处和日期。
5. **整理交付**：使用 `assets/templates/dev-spec.md`，每项需求都写输入、预期行为、异常条件和验收方法。

### 如何验收策划文档

- 开发能否从文档理解开始、胜利、失败和重新开始的条件？
- 首批关卡是否列出具体规则，而不是只有“越来越难”？
- 广告、内购、剧情和素材范围是否清晰，假设是否标注？
- 未核实的主体资格、版号和审核要求是否列为待核实项？

### 常见问题

| 现象 | 处理方法 |
|---|---|
| 我想直接得到小游戏 | 本仓库只负责策划；将规格文档交给开发人员或开发工具实现 |
| 没预算、没团队也能用吗 | 可以先做可行性分析，把缺失条件标为待定 |
| 是否保证通过审核 | 不保证，文档不能替代官方审核或专业法律意见 |
| 文档里政策判断很绝对 | 旧的静态表述不可直接作为当前结论；要求附当时官方出处并核对适用范围 |


### 更新与反馈

ZIP 安装用户先备份自己的修改和产出，再下载新版本替换技能文件。Git 安装用户在没有本地修改时可在仓库目录执行 `git pull --ff-only`；有修改时先保存，避免覆盖。更新后重新打开会话。遇到问题请在 [Issues](https://github.com/fantasyo123/minigame-design-consultant/issues) 提供宿主名称、操作步骤、预期结果和脱敏后的错误信息。

## 详细能力与原有参考

> 把微信小游戏的玩法创意，变成可评审、可交付给开发团队的策划方案。策划侧全流程：立项 → 核心循环 → 关卡机制 → 美术 UX → 剧情 → 变现 → 合规 → 交付规格。

一个可移植的 Agent Skill 包：WorkBuddy / Claude Code / Codex 等支持 `SKILL.md` 约定的 Agent 均可直接加载。它是**策划与体验设计顾问**，不写游戏工程代码。

## 它解决什么问题

大多数"我想做个小游戏"会卡在三个地方：玩法说不清、版号没算进排期、给开发的文档没法验收。这个 skill 用一套阶段化工作流把三件事钉住：

| 阶段 | 产出 | 解决的问题 |
|---|---|---|
| 0 · 诊断 | 立项决策卡 | 能不能做、卡在哪、要多久 |
| 1 · 核心循环 | 循环图 + 留存付费表 | 凭什么留住人 |
| 2 · 关卡机制 | 机制矩阵 + 难度曲线 + 数值表 | 内容怎么排 |
| 3 · 美术 UX | 风格三件套 + 首 60 秒脚本 | 长什么样、第一分钟怎么留人 |
| 3b · 剧情 | 体量档位 + 对话脚本格式 | 内容成本可控 |
| 4 · 合规 | 提审自测清单 + 驳回原因库 | 会不会被拒 |
| 5 · 变现 | 广告位 + 内购边界 | 靠什么赚钱 |
| 6 · 交付 | 开发规格说明书 + 验收标准 | 开发不用回来问 |

## 形态区分与政策核查

1. **形态差异**：小游戏 ≠ 小程序。无 WXML/WXSS，Canvas/WebGL 渲染，`game.js` + `game.json` 入口，包体与开放数据域能力都不同。
2. **主体资格**：按实际产品与当前微信平台要求核对可注册主体和支持类目，记录官方出处与日期。
3. **上线与变现资质**：按上线地区、游戏类型与变现方式核对出版、备案及平台所需材料；未核实前列为排期阻塞项，不承诺固定周期。

> 政策与平台限额会更新。本仓库只给判断框架与查证入口，具体数字以[国家新闻出版署](https://www.nppa.gov.cn/)与[微信开放社区](https://developers.weixin.qq.com/community/)最新公告为准。

```

```

## 范围边界

- ✅ 创意策划、核心循环、关卡机制、美术 UX、剧情规划、变现设计、合规要点、交付规格
- ❌ 不写游戏工程代码（只给行为描述与接口契约）
- ❌ 不代申请版号软著、不伪造材料、不提供绕过审核的方法
- ❌ 不出具具有法律效力的合规背书（由持证出版单位与法务承担）
